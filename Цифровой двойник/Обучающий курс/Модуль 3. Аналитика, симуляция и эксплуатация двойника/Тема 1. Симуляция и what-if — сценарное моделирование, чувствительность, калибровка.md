# Модуль 3. Тема 1. Симуляция и what-if — сценарное моделирование, чувствительность, калибровка

> Модуль 3 «Аналитика, симуляция и эксплуатация двойника» · Тема 1 из 7

## Учебные цели

После изучения темы студент сможет:

- сформулировать корректную постановку what-if эксперимента: базовый сценарий, варианты, управляемые параметры и внешние факторы;
- спланировать серию расчётов методами DoE — полный перебор сетки, латинский гиперкуб, Монте-Карло — и обосновать выбор числа прогонов;
- провести анализ чувствительности локальным (OAT) и глобальным методами и построить торнадо-диаграмму;
- откалибровать модель по фактическим данным, задав целевую функцию и разделив выборку на калибровочную и проверочную;
- оформить результат в виде протокола сценарного эксперимента, пригодного для повторения другим человеком.

## Ключевые понятия

| Термин | Определение |
|--------|-------------|
| Симуляция | Прогон модели во времени или по состояниям для получения расчётных значений выходов при заданных входах |
| What-if сценарий | Расчёт «что будет, если» при изменении набора входных величин относительно базового варианта |
| Базовый сценарий (baseline) | Опорный вариант расчёта, с которым сравниваются все остальные; фиксируется первым и не меняется в ходе серии |
| Управляемый параметр | Величина, на которую пользователь системы может влиять решением (мощность, график, объём инвестиций) |
| Внешний фактор | Величина, которая задаётся средой и не управляется (погода, цены, спрос, демография) |
| DoE (design of experiments) | Планирование эксперимента — правило выбора точек в пространстве входных величин |
| Латинский гиперкуб (LHS) | Стратифицированная выборка, покрывающая диапазон каждого входа равномерно при малом числе прогонов |
| Монте-Карло | Многократный прогон модели со случайными входами из заданных распределений для получения распределения выхода |
| Чувствительность | Мера того, насколько выход модели реагирует на изменение конкретного входа |
| Калибровка | Подбор значений внутренних параметров модели так, чтобы расчёт совпал с наблюдаемым фактом |
| Верификация допущений | Явная фиксация упрощений модели и границ, за которыми сценарий не имеет силы |

## Постановка what-if эксперимента

What-if расчёт без формальной постановки превращается в набор несравнимых цифр. Минимальная постановка включает шесть элементов.

| Элемент | Вопрос, на который он отвечает | Пример |
|---------|-------------------------------|--------|
| Управленческий вопрос | Какое решение принимается по итогу | Строить ли второй склад в узле |
| Метрика решения | По какому числу сравниваются варианты | Суммарные логистические затраты за год |
| Управляемые параметры | Что меняем сами | Наличие склада, его ёмкость, число смен |
| Внешние факторы | Что задано средой и варьируется как неопределённость | Спрос, тариф на перевозку, доля отказов |
| Ограничения | Что нельзя нарушать ни в одном варианте | Бюджет, нормативы надёжности, пропускная способность |
| Горизонт и шаг | На какой период и с какой дискретностью считаем | 3 года, шаг — месяц |

Правило разделения: если величина не может быть изменена решением того пользователя, для которого готовится расчёт, она относится к внешним факторам. Одна и та же величина у разных пользователей попадает в разные группы — тариф управляем для регулятора и внешний для перевозчика.

```
Базовый сценарий -> [фиксируем допущения и данные]
        |
        +-- Вариант A: изменены управляемые параметры
        +-- Вариант B: изменены управляемые параметры
        |
        +-- по каждому варианту: разброс внешних факторов (Монте-Карло)
        |
        v
Сравнительная таблица: метрика решения, разброс, нарушенные ограничения
```

## Планирование серии расчётов (DoE)

Пространство входов почти всегда больше, чем можно перебрать. Выбор плана — компромисс между покрытием и стоимостью прогонов.

| План | Число прогонов | Когда применять | Ограничение |
|------|----------------|-----------------|-------------|
| Ручной набор сценариев | 3–7 | Управленческое сравнение немногих альтернатив | Не даёт чувствительности и распределений |
| Полная сетка (grid) | k^n при n входах | 2–3 входа, дешёвая модель | Комбинаторный взрыв |
| Дробный факторный план | Десятки | Скрининг: отсев незначимых входов | Смешивание эффектов взаимодействия |
| Латинский гиперкуб | 10n–100n | Много входов, дорогой прогон | Требует заданных диапазонов |
| Монте-Карло | Сотни–тысячи | Оценка распределения и хвостовых рисков | Нужны распределения входов, не только диапазоны |

Практическое правило: сначала скрининг дешёвым планом, отсев входов с малым вкладом, затем плотный план по 3–6 оставшимся.

Учебный пример объёма: модель с 8 входами. Полная сетка по 5 уровням — 5^8 = 390 625 прогонов. При 4 секундах на прогон это около 18 суток счёта. Латинский гиперкуб на 400 точек занимает менее получаса и даёт достаточную оценку чувствительности для скрининга.

## Анализ чувствительности

Цель — ответить, какие входы реально определяют результат, а какие можно зафиксировать константой.

**Локальный анализ (OAT, one-at-a-time).** Каждый вход по очереди отклоняется от базового значения на ±X процентов, остальные удерживаются. Даёт наглядную торнадо-диаграмму, но не видит взаимодействий между входами и справедлив только около базовой точки.

**Глобальный анализ.** Входы варьируются совместно по всему диапазону; вклад оценивается через дисперсионное разложение (индексы Соболя) или ранговую корреляцию входов с выходом. Дороже по числу прогонов, но корректен для нелинейных моделей.

Учебный пример торнадо-диаграммы. Базовые логистические затраты — 100 условных единиц; каждый вход отклоняется на ±20 процентов.

| Вход | Затраты при −20 % | Затраты при +20 % | Размах | Доля размаха |
|------|-------------------|-------------------|--------|--------------|
| Тариф на перевозку | 88 | 112 | 24 | 46 % |
| Объём спроса | 92 | 109 | 17 | 33 % |
| Доля порожнего пробега | 96 | 104 | 8 | 15 % |
| Стоимость хранения | 98,5 | 101,5 | 3 | 6 % |

```
Тариф на перевозку   |=============================|   24
Объём спроса         |=====================|           17
Порожний пробег      |==========|                        8
Стоимость хранения   |====|                              3
                     0        10        20        30
```

Вывод для проектирования: точность тарифа и спроса определяет качество ответа; на уточнение стоимости хранения ресурсы тратить нецелесообразно. Именно так анализ чувствительности превращается в требования к данным для модуля 2.

## Калибровка модели по фактическим данным

Калибровка — подбор внутренних параметров (коэффициенты сопротивления, доли потерь, эластичности), которые нельзя измерить напрямую, по наблюдаемым парам «вход — факт».

Порядок работы:

1. Разделить исторические данные на калибровочный и проверочный периоды; проверочный не используется при подборе.
2. Задать целевую функцию — например, сумму квадратов отклонений расчёта от факта либо MAE, если важна устойчивость к выбросам.
3. Ограничить область поиска физически осмысленными пределами каждого параметра.
4. Подобрать параметры: перебор по сетке для 1–2 параметров, покоординатный спуск или градиентные методы для гладких задач, эволюционные и байесовские методы для дорогих и шумных моделей.
5. Проверить результат на проверочном периоде и зафиксировать обе метрики.

Формула целевой функции в текстовом виде: `J(p) = сумма по i от 1 до N ( (факт_i − модель_i(p))^2 ) / N`, минимизируем `J` по вектору параметров `p`.

Учебный числовой пример. Модель потребления энергии узла: `Расход = a * Выпуск + b`. Данные четырёх месяцев:

| Месяц | Выпуск, тыс. ед. | Факт расхода, МВт·ч |
|-------|------------------|---------------------|
| 1 | 10 | 62 |
| 2 | 14 | 78 |
| 3 | 12 | 71 |
| 4 | 16 | 87 |

Подбор по методу наименьших квадратов даёт примерно `a = 4,1`, `b = 21`. Расчётные значения: 62, 78,4, 70,2, 86,6. Средняя абсолютная ошибка на калибровочном периоде — около 0,5 МВт·ч. На пятом месяце (выпуск 20) модель предсказывает 103; факт — 108, ошибка 4,6 %. Расхождение выше калибровочного означает, что при выпуске за пределами диапазона 10–16 линейное допущение начинает нарушаться — это и есть граница применимости, о которой подробнее в теме 6.

**Переобучение калибровки.** Если параметров столько же, сколько наблюдений, модель воспроизведёт историю идеально и провалится на новых данных. Признаки: ошибка на калибровке близка к нулю, на проверке — в разы выше; подобранные параметры физически абсурдны (отрицательный КПД, эластичность больше единицы). Средства: сокращение числа свободных параметров, ограничения на их значения, кросс-валидация по периодам.

## Протокол сценарного эксперимента (шаблон)

| Поле | Содержание |
|------|------------|
| Идентификатор | SIM-2026-014 |
| Управленческий вопрос | Формулировка решения, которое принимается |
| Владелец расчёта | Роль и подразделение |
| Модель и версия | Имя, версия, ссылка на паспорт модели |
| Версия данных | Срез входных данных с датой и источником |
| Базовый сценарий | Значения всех входов |
| Варианты | Перечень изменённых величин по каждому варианту |
| План эксперимента | Тип DoE, число прогонов, генератор случайных чисел и его seed |
| Метрики | Метрика решения и вспомогательные показатели |
| Допущения и упрощения | Явный список |
| Границы применимости | Диапазоны входов, за которыми результат недействителен |
| Результат | Таблица сравнения, распределения, чувствительность |
| Вывод и рекомендация | Что рекомендуется и с какой оговоркой |

Фиксация seed генератора обязательна: без него результат Монте-Карло невоспроизводим, и повторный расчёт даст другие цифры, что подрывает доверие к системе.

## Типичные ошибки

| Ошибка | Почему возникает | Как избежать |
|--------|------------------|--------------|
| Сравнение вариантов, посчитанных на разных срезах данных | Данные обновились между прогонами | Фиксировать версию данных на всю серию, указывать её в протоколе |
| Смешение управляемых параметров и внешних факторов | Не определён пользователь расчёта | Определять роль-заказчика до постановки эксперимента |
| Один прогон вместо распределения | Экономия времени, привычка к детерминированным расчётам | Минимум — три точки (пессимистичная, базовая, оптимистичная), лучше Монте-Карло |
| Локальная чувствительность выдаётся за глобальную | OAT дешевле и нагляднее | Проверять нелинейные модели глобальными методами |
| Калибровка на всей истории без проверочного периода | Стремление к минимальной ошибке | Всегда откладывать проверочный период и публиковать обе метрики |
| Экстраполяция сценария за диапазон калибровки без оговорки | Модель формально считает любые входы | Программно помечать результаты вне области валидности |
| Невоспроизводимый результат | Не сохранены seed, версии, конфигурация | Протокол эксперимента как обязательный артефакт |

## Пример: «Цифровой двойник России»

В документе [Тезисы](../../Тезисы.md) сценарное моделирование заявлено как основная функция системы (тезис 5), а в качестве минимального набора названы пять сценариев: запуск нового производства, изменение транспортной схемы, переобучение под отраслевой запрос, реакция на ЧС, сравнение инвестиционных площадок. Там же зафиксированы принципы моделирования: результаты сопровождаются ограничениями и допущениями, модели версионируются вместе с данными, пользователю видна цепочка расчёта, а спорные сценарии проверяются на нескольких независимых моделях. Эти четыре принципа полностью совпадают с требованиями к протоколу эксперимента, описанному выше.

Сценарий 1.3 «Сравнение сценариев развития региона» из [Сценариев](../../Сценарии.md) — прямой пример what-if постановки: пользователь (региональный орган стратегического планирования), горизонт 5–10 лет, результат в виде таблицы сценариев с показателями устойчивости, занятости, ВРП и нагрузки. Управляемые параметры здесь — объём и адресность инвестиционных программ; внешние факторы — демография, климат, экономическая конъюнктура. Контур доступа — ведомственный, то есть протокол эксперимента и исходные значения остаются внутри контура, а наружу может уходить только агрегированный вывод.

В [Примерах обработки информации для контуров](../../Примеры%20обработки%20информации%20для%20контуров.md) ведомственный пример прямо описывает сценарную развилку: «текущая программа подготовки», «расширенный набор», «программа переобучения», «привлечение из соседних регионов» с оценкой стоимости и сроков по каждому варианту. Это готовая четырёхвариантная what-if серия с общим базовым сценарием и единой метрикой решения — покрытие кадрового дефицита при заданном бюджете.

## Практическое задание

Для сквозного проекта (цифровой двойник объекта или процесса, выбранный в модуле 1) подготовьте и проведите сценарный эксперимент.

1. Сформулируйте управленческий вопрос и метрику решения.
2. Разделите входы на управляемые параметры и внешние факторы, укажите диапазоны для каждого.
3. Постройте базовый сценарий и не менее трёх вариантов.
4. Проведите локальный анализ чувствительности по всем входам и постройте торнадо-таблицу.
5. Для двух самых значимых входов выполните расчёт Монте-Карло не менее чем на 200 прогонов и приведите распределение метрики решения.
6. Оформите протокол эксперимента по шаблону из темы.

Критерии приёмки:

- [ ] управленческий вопрос сформулирован как выбор между конкретными альтернативами, а не как «посмотреть, что будет»;
- [ ] базовый сценарий описан полностью и не меняется между вариантами;
- [ ] каждый вход отнесён к управляемым или внешним с обоснованием через роль пользователя;
- [ ] торнадо-таблица содержит размах и долю размаха по каждому входу;
- [ ] для Монте-Карло указаны распределения входов, число прогонов и seed;
- [ ] приведены медиана и перцентили 10 и 90 по метрике решения;
- [ ] явно перечислены допущения и границы применимости результата;
- [ ] протокол позволяет другому студенту воспроизвести расчёт без устных пояснений.

## Проверочные вопросы

1. Чем базовый сценарий отличается от варианта и почему его нельзя изменять в ходе серии?
2. Одна и та же величина может быть управляемым параметром и внешним фактором. От чего это зависит?
3. В каком случае латинский гиперкуб предпочтительнее полной сетки и почему?
4. Какие выводы нельзя делать по результатам локального OAT-анализа?
5. Что показывает и чего не показывает торнадо-диаграмма?
6. По каким признакам распознаётся переобученная калибровка?
7. Зачем в протоколе эксперимента фиксируется seed генератора случайных чисел?

- [ISO/IEC 30173:2023 «Digital twin — Concepts and terminology»](https://www.iso.org/standard/81442.html)
- [ГОСТ Р 57700.37-2021 «Компьютерные модели и моделирование. Цифровые двойники изделий. Общие положения»](https://www.gostinfo.ru/catalog/Details/?id=6869870)
- ASME V&V 10 — руководство по верификации и валидации в вычислительной механике твёрдого тела (терминология верификации, валидации и оценки неопределённости).
- ASME V&V 20 — руководство по оценке неопределённости при валидации вычислительных расчётов.
- [Digital Twin Consortium](https://www.digitaltwinconsortium.org/) — отраслевые материалы и терминология по цифровым двойникам.
