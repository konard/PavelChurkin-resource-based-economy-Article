# Модуль 3. Тема 2. Диагностика и прогноз — состояния, аномалии, износ, предиктивное обслуживание

> Модуль 3 «Аналитика, симуляция и эксплуатация двойника» · Тема 2 из 7

## Учебные цели

После изучения темы студент сможет:

- построить классификацию состояний объекта и выбрать между пороговой и модельной диагностикой;
- применить методы обнаружения аномалий (статистические, по остаткам модели, машинное обучение) и оценить их качество через precision, recall и время до обнаружения;
- рассчитать прогноз остаточного ресурса (RUL) по кривой деградации и интерпретировать P-F интервал;
- обосновать выбор стратегии обслуживания — реактивной, планово-предупредительной, по состоянию или предиктивной — для конкретного узла;
- связать результаты FMEA с перечнем диагностируемых признаков и оценить экономический эффект перехода к предиктивному обслуживанию.

## Ключевые понятия

| Термин | Определение |
|--------|-------------|
| Состояние объекта | Дискретная характеристика работоспособности: норма, отклонение, предотказ, отказ, вывод из работы |
| Диагностика | Определение текущего состояния и причины отклонения по наблюдаемым данным |
| Прогностика | Оценка будущего состояния и момента достижения предельного значения |
| Аномалия | Наблюдение, статистически несовместимое с ожидаемым поведением объекта |
| Остаток (residual) | Разность между фактическим измерением и расчётом модели для тех же условий |
| RUL (remaining useful life) | Остаточный ресурс — время или наработка до достижения предельного состояния |
| P-F интервал | Промежуток от момента, когда отказ становится обнаружимым (P), до собственно отказа (F) |
| Precision / Recall | Доля верных срабатываний среди всех тревог / доля обнаруженных дефектов среди всех реальных |
| MTBF | Средняя наработка между отказами |
| FMEA | Анализ видов, последствий и критичности отказов |
| Дрейф уставки | Постепенное смещение нормального уровня признака, не связанное с дефектом |

## Классификация состояний и два подхода к диагностике

Базовая шкала состояний должна быть согласована до выбора алгоритмов, иначе тревоги невозможно интерпретировать.

| Состояние | Признак | Действие |
|-----------|---------|----------|
| Норма | Все контролируемые признаки в допуске | Наблюдение |
| Отклонение | Признак вышел за рабочий диапазон, но ниже предаварийного | Проверка данных, наблюдение с повышенной частотой |
| Предотказ | Устойчивый тренд к предельному значению или обнаружен дефект-предвестник | Планирование работ в ближайшее окно |
| Отказ | Функция не выполняется | Аварийные работы |
| Вне эксплуатации | Объект остановлен планово или аварийно | Расчёт исключается из статистики |

**Пороговая диагностика.** Признак сравнивается с константой (уставкой). Просто, прозрачно, легко объясняется оператору. Недостаток — уставка не учитывает режим: температура 78 °C при полной нагрузке нормальна, а на холостом ходу означает дефект.

**Модельная диагностика.** Двойник вычисляет ожидаемое значение признака для текущих условий, а тревога выдаётся по остатку `r = факт − расчёт`. Такой подход учитывает режим, но требует валидной модели и отдельного контроля её собственной деградации.

```
Условия работы ---> [ модель двойника ] ---> ожидание
                                                 |
Измерение ------------------------------------> ( − ) ---> остаток r
                                                              |
                                                 [ правило: |r| > k*sigma длительностью T ]
                                                              |
                                                              v
                                                          состояние
```

## Обнаружение аномалий

| Метод | Что находит | Требования | Ограничения |
|-------|-------------|------------|-------------|
| Правило по уставке | Грубые выходы за диапазон | Знание допусков | Не видит режимозависимых дефектов |
| Контрольные карты, правило 3 сигм | Смещение среднего, рост разброса | Стационарный процесс | Ложные тревоги при смене режима |
| Анализ остатков модели | Расхождение факта и физики | Валидная модель | Ошибка модели маскируется под дефект |
| Кластеризация, изолирующий лес | Многомерные нетипичные сочетания | Достаточная история нормы | Слабая интерпретируемость |
| Автоэнкодер, прогноз временного ряда | Сложные многомерные шаблоны | Большой объём данных, MLOps | Требует переобучения при смене режима |

Различают точечные аномалии (одиночный выброс — часто дефект датчика), контекстные (значение нормально само по себе, но не для данного режима или сезона) и коллективные (последовательность значений в целом аномальна, хотя каждое значение в допуске — типичный признак развивающегося износа).

**Метрики качества.** Для диагностики важны не только precision и recall, но и оперативность.

| Метрика | Формула в текстовом виде | Управленческий смысл |
|---------|--------------------------|----------------------|
| Precision | TP / (TP + FP) | Доверие персонала к тревогам |
| Recall | TP / (TP + FN) | Доля пропущенных дефектов |
| F1 | 2 · P · R / (P + R) | Свёртка при сопоставимой цене ошибок |
| Доля ложных срабатываний | FP / число всех тревог | Нагрузка на оперативный персонал |
| Время до обнаружения | Момент тревоги − момент начала дефекта | Запас времени на реакцию |

Учебный пример. За квартал система выдала 120 тревог, из них 30 подтверждены как реальные дефекты. Реальных дефектов было 36 (6 пропущено). Precision = 30/120 = 0,25; recall = 30/36 = 0,83. Каждая проверка стоит 8 тысяч рублей, а пропущенный отказ — 900 тысяч. Затраты на ложные проверки: 90 × 8 = 720 тысяч; потери от пропусков: 6 × 900 = 5400 тысяч. Смещение порога в сторону чувствительности оправдано, пока прирост ложных проверок дешевле сокращения пропусков. Это и есть корректный способ выбора порога — не по F1, а по стоимости ошибок.

## Прогноз износа и остаточный ресурс

Кривая деградации связывает наработку с показателем состояния. Типичные формы: линейная (равномерный износ), степенная (ускоряющееся развитие трещины), экспоненциальная (лавинообразная стадия). RUL — время от текущего момента до пересечения кривой с предельным значением.

```
Показатель
деградации  |                                  предел ----
            |                              ..../
            |                       ....../
            |   ............./
            +-------------------------------------------> наработка
                     P                          F
                     |<------- P-F интервал ------>|
```

Практический смысл P-F интервала: частота контроля должна быть меньше половины P-F интервала, иначе дефект успевает развиться между проверками. Если P-F интервал вибрационного дефекта подшипника — 60 суток, контроль реже одного раза в 30 суток бессмыслен независимо от качества алгоритма.

Учебный расчёт RUL. Толщина стенки трубопровода: 12,0 мм при вводе, 10,8 мм через 4 года, предельная — 8,0 мм.

- Скорость коррозии: (12,0 − 10,8) / 4 = 0,3 мм в год.
- Запас до предела: 10,8 − 8,0 = 2,8 мм.
- RUL = 2,8 / 0,3 ≈ 9,3 года.

Оценка точечная и потому неполная. Если разброс скорости коррозии по замерам составляет ±0,08 мм в год, консервативная оценка при 0,38 мм в год даёт RUL ≈ 7,4 года. Планировать замену следует по нижней границе интервала, а не по средней: прогноз без интервала неопределённости в эксплуатации применять нельзя.

## Стратегии обслуживания

| Стратегия | Когда выполняются работы | Условия применимости | Основной недостаток |
|-----------|--------------------------|----------------------|---------------------|
| Реактивная (до отказа) | После отказа | Дешёвый некритичный узел, есть резерв, отказ не каскадный | Внеплановые простои |
| Планово-предупредительная | По календарю или наработке | Известен закон износа, отказ дорогой | Замена работоспособных узлов |
| По состоянию (CBM) | По факту достижения порога признака | Есть измеримый признак деградации | Требует контроля и уставок |
| Предиктивная (PdM) | По прогнозу RUL с горизонтом планирования | Есть история отказов, модель и P-F интервал достаточной длины | Стоимость данных и моделей, риск ложных прогнозов |

Переход к предиктивной стратегии оправдан не всегда. Он даёт эффект, когда одновременно выполняются четыре условия: отказ дорогой или опасный; существует наблюдаемый предвестник; P-F интервал длиннее срока подготовки работ; есть история для настройки модели. Если хотя бы одно условие не выполнено, дешевле остаться на планово-предупредительной схеме.

## Связь с FMEA

FMEA задаёт перечень того, что вообще следует диагностировать. Для каждого вида отказа фиксируются последствия, причины, признак-предвестник и метод контроля — это прямое техническое задание на диагностические алгоритмы двойника.

| Узел | Вид отказа | Последствие | Признак-предвестник | Метод контроля | Приоритет |
|------|------------|-------------|---------------------|----------------|-----------|
| Насосный агрегат | Разрушение подшипника | Останов линии на 8 ч | Рост вибрации на характерных частотах | Вибродиагностика, тренд | Высокий |
| Трубопровод | Утечка от коррозии | Экологический ущерб, штраф | Падение толщины стенки, дисбаланс расходов | Толщинометрия, баланс потоков | Высокий |
| Теплообменник | Загрязнение поверхности | Снижение КПД на 10–15 % | Рост перепада температур при той же нагрузке | Остаток модели теплообмена | Средний |
| Датчик расхода | Дрейф показаний | Ошибочные решения по всей цепочке | Расхождение с расчётным балансом | Кросс-проверка по модели | Средний |

Правило: если для вида отказа не найден наблюдаемый признак, никакая аналитика его не обнаружит — задача переносится на изменение состава датчиков (модуль 2, тема 2), а не на алгоритмы.

## Учебный расчёт эффекта предиктивного обслуживания

Парк из 40 однотипных насосных агрегатов.

| Показатель | До внедрения | После внедрения |
|------------|--------------|-----------------|
| Внеплановых отказов в год | 12 | 4 |
| Средний простой на отказ, ч | 9 | 9 |
| Стоимость часа простоя, тыс. руб. | 150 | 150 |
| Плановых замен узлов в год | 40 | 26 |
| Стоимость замены узла, тыс. руб. | 120 | 120 |

- Потери от простоев: было 12 × 9 × 150 = 16 200 тыс. руб.; стало 4 × 9 × 150 = 5 400 тыс. руб. Экономия 10 800 тыс. руб.
- Затраты на замены: было 40 × 120 = 4 800 тыс. руб.; стало 26 × 120 = 3 120 тыс. руб. Экономия 1 680 тыс. руб.
- Суммарная экономия — 12 480 тыс. руб. в год.
- Затраты на систему: датчики и монтаж 6 000 тыс. руб. единовременно, эксплуатация и сопровождение моделей 2 400 тыс. руб. в год.
- Эффект первого года: 12 480 − 6 000 − 2 400 = 4 080 тыс. руб. Простой срок окупаемости — около 7 месяцев с начала работы системы.

Расчёт обязан включать стоимость сопровождения моделей: без переобучения и перекалибровки качество прогноза падает, и эффект второго года окажется ниже расчётного (см. тему 6).

## Типичные ошибки

| Ошибка | Почему возникает | Как избежать |
|--------|------------------|--------------|
| Уставка без учёта режима | Простота настройки | Переходить к остаткам модели или уставкам по режимам |
| Оценка алгоритма только по accuracy | Дефекты редки, доля верных ответов почти 100 % при полном бездействии | Использовать precision, recall и стоимость ошибок |
| Тревоги без указания причины и действия | Алгоритм отделён от эксплуатационного регламента | Каждая тревога сопровождается кодом причины и предписанным действием |
| Игнорирование P-F интервала при выборе частоты контроля | Частота задана административно | Считать частоту от P-F интервала |
| Точечный прогноз RUL без интервала | Так проще отчитываться | Планировать по нижней границе доверительного интервала |
| Дефект датчика принимается за дефект оборудования | Нет кросс-проверки измерений | Валидация датчиков по балансам и резервным измерениям |
| Предиктивная стратегия для всех узлов подряд | Мода на технологию | Отбор узлов по критичности и наличию предвестника |

## Пример: «Цифровой двойник России»

В [Описании](../../Описание.md) в перечне услуг присутствует «Мониторинг критической инфраструктуры — выявление зависимостей, точек отказа и потребности в резервировании». Это диагностическая задача, но масштабированная с отдельного агрегата на сеть: состояние оценивается не только по узлу, но и по последствиям его отказа для смежных систем.

В [Примерах обработки информации для контуров](../../Примеры%20обработки%20информации%20для%20контуров.md) инфраструктурный пример описывает моделирование отказа одной линии, одной подстанции, одного резерва с оценкой времени восстановления и зон, остающихся без питания, а также поиск зависимостей с водоснабжением, связью, транспортом и медициной. По логике FMEA это анализ последствий отказа на сетевом уровне: перечень критических элементов, полученный таким расчётом, задаёт приоритеты мониторинга — где нужен непрерывный контроль состояния, а где достаточно периодической отчётности.

Существенное ограничение проекта: результаты такого анализа сами являются чувствительными. Тот же документ прямо требует, чтобы инфраструктурный контур отдавал наружу ограничения и условия, а не схемы и точки отказа. Поэтому диагностическая панель по критической инфраструктуре живёт внутри инфраструктурного контура, в ведомственный уходит вывод о допустимости решения, а в открытый — только факт согласования. Детали разграничения рассматриваются в теме 7.

## Практическое задание

Для сквозного проекта разработайте диагностический и прогностический контур одного узла.

1. Опишите шкалу состояний объекта (не менее четырёх состояний) с признаками и действиями.
2. Проведите упрощённый FMEA не менее чем для трёх видов отказа с указанием признака-предвестника и метода контроля.
3. Для одного вида отказа задайте правило обнаружения (порог или остаток модели) и обоснуйте параметры: порог, длительность подтверждения, гистерезис.
4. Постройте кривую деградации по историческим или синтетическим данным и рассчитайте RUL с интервалом неопределённости.
5. Выберите стратегию обслуживания для узла и подтвердите выбор расчётом годового эффекта.

Критерии приёмки:

- [ ] шкала состояний согласована с действиями эксплуатационного персонала;
- [ ] в FMEA для каждого вида отказа указан наблюдаемый признак либо явно отмечено его отсутствие;
- [ ] правило обнаружения содержит порог, длительность подтверждения и условие снятия тревоги;
- [ ] качество обнаружения оценено через precision, recall и время до обнаружения;
- [ ] выбор порога обоснован стоимостью ложных срабатываний и пропусков, а не только F1;
- [ ] прогноз RUL приведён с интервалом, а решение принято по нижней границе;
- [ ] частота контроля сопоставлена с P-F интервалом;
- [ ] расчёт эффекта включает затраты на сопровождение моделей.

## Источники

- ISO 13374 — серия стандартов по мониторингу состояния и диагностике машин: обработка данных, обмен информацией и представление результатов.
- ISO 55000 — серия стандартов по управлению активами: обзор, принципы и терминология, требования к системе менеджмента активов.
- [ISO 23247 «Digital twin framework for manufacturing»](https://www.iso.org/standard/75066.html)
- [ГОСТ Р 57700.37-2021 «Цифровые двойники изделий. Общие положения»](https://www.gostinfo.ru/catalog/Details/?id=6869870)
